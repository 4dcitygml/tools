# 都市データと道具をともに育てる

**オープンソース文化を、都市データと、それを支える仕組みに広げる。**
共有して使い、気づきを返し、みんなで育てる。

| 共通する循環 | 都市データを育てる | 共通の道具・運用を育てる |
|---|---|---|
| 使う | CityGMLを利用する | 共通処理・検査を利用する |
| 気づきを返す | 建物情報の誤りや変化を投稿する | 見逃し・過剰な警告・未対応の事例を共有する |
| 確かめて改善する | 根拠を確認し、検査・承認してデータを更新する | 事例を再現し、処理・検査・説明を改善する |
| 再び共有する | 更新データを公開する | 共通リリースで各都市へ届ける |

都市側は普段のIssue・PRに問題と対応の経緯を残します。4dcitygml側が再利用できる事例を集め、共通化のための転記や整理を引き受けます。都市だけで解決できない問題は、4dcitygmlへ直接相談できます。原因や修正方法を知っていることは、相談の前提ではありません。

独立して進められる都市の対応は進め、共通改修に依存する対応は連携して解決します。処理結果の再現と、資料や解釈の妥当性は別です。採用には対象に応じた人の確認が必要であり、道具の改善と都市データの承認を同じ判断にはしません。

運用層は、都市の個別事例と共通の規格をつなぐ役割を担います。規格を使える処理・検査にし、現場の経験を再利用できる改善へ変え、データや実装の問題と規格上の課題を切り分けます。必要な場合は再現事例と要件を規格策定側へ提供します。規格の採用判断は策定側にあり、特定団体との正式な連携が既に成立しているという意味ではありません。

実装は段階的に進めます。一度の試験成功で任意の一括更新を利用可能とはしません。[実装状況（英語）](../implementation-status.md)と[配布方法（英語）](../shared-tooling-release.md)に、対応範囲と残作業を示します。
