# CityGML 属性エディタ

建物属性の確認・編集に特化した軽量ローカルツール。
「2D 地図で建物を選ぶ → 属性を一望 → 直して PR」の 1 フローだけを提供する、
提出者用のフロントエンドです（レビューは既存 CI と GitHub が担当）。

## 起動

このクローンの中から起動するだけです（`--repo` は自動検出。依存は Python 3.9+ のみ。
macOS はコマンドラインツール同梱の python3 でそのまま動きます）:

```bash
python3 tools/attr_editor/app.py        # → http://localhost:8765 が開く
```

> **住民・自治体職員の方へ**: エディタはハブから起動します。ハブは都市の README にある
> 一行コマンドで入ります（ハブの README を参照）。ハブが都市の使う GitHub アカウントを
> 保持し、データを最新に保ち、そのアカウントでこのエディタを起動します。エディタ単体の
> 配布はもうありません（以前の単体 zip は hub-v1.2 で廃止）。

- UI は Leaflet / Cesium を CDN から読みます（地図タイル以外はオフライン動作）。
- 変更案（PR）は、ハブがその都市に記録したアカウント（`~/.citygml/auth/<login>.json`）で
  開きます。パソコン自身の GitHub ログインは決して使いません。アカウントが無ければ送信は
  何も起きる前に止まり、画面がハブの設定へ案内します。ハブを経由しない場合は GitHub の
  画面の compare URL で終わります。
- データパッケージが複数ある場合は最大のものを自動選択（`--data 13101` で明示可）。

## 使い方

1. 地図上のメッシュ枠をクリック → 建物フットプリントが表示される（初回パース数秒）
2. 建物クリック → 地図の下に**実際の位置で3Dプレビュー**、右パネルに属性カード
   （LOD1／LOD2を切替可能。LOD2を持たない建物ではLOD2とテクスチャのボタンをグレーアウト。
   `?tile=&bid=` を URL で共有可）
3. 値クリックでインライン編集（コードリストはドロップダウン）→ 変更は黄色表示
4. 値を確定すると同じ行に**出典の必須選択欄**が開く → 確認した資料を選ぶ
   （「不明」「未作成」は新しい変更の出典には選べない。未選択の属性が1つでもある間は送信不可）
5. 出典コードを選ぶと、[出典記録ルール](https://github.com/4dcitygml/city-template/blob/main/docs/provenance-rules.md) の解決規則に従って
   gen「出典」セットへ項目特記を追加。上位に無いコードは `thematicSrcDesc` にも自動追記＝R2-8。
   同名複数で項目特記できない属性は建物単位の出典を同期し、属性との対応を PR 本文へ残す
6. 「変更内容を送る」→ 必要ならURLや補足を追記 → **提出前チェック**（対象1棟・XML形式・
   変更ファイル範囲・出典連動）に合格 → 管理者が確認する変更案を自動作成

PR のタイトルと本文は、変更した項目・変更前後・選択した出典から自動生成します。たとえば
「『現地調査』を確認し、『地上階数』を『2』から『3』に修正しました」のような日本語になり、
XML のタグ名を知らない管理者も変更理由を読めます。この生成テキストは、読者が都市の
レビュアーであるため**リポの作業言語**（`4dcitygml.json` の `lang`）で書かれます。
画面の言語と異なる場合はプレビューの上に注記が出ます（hub README の「言語ポリシー」参照）。画面だけでなく送信 API でも全属性の出典を
再検証するため、値だけの変更案は作成できません。

## 構成と設計

| ファイル | 役割 |
|---|---|
| `app.py` | ローカル HTTP サーバ（GML パース・JSON API・葉値置換・git/PR） |
| `index.html` | 2D 地図 + 属性パネル + 編集 + PR UI |
| `viewer.html` | Cesium による 1 棟 3D 表示（`?tile=<メッシュ>&bid=<gml:id>`） |

- メッシュ選択は意図的に手動です。利用者がメッシュ枠をクリックしてから、そのメッシュの建物
  フットプリントを読み込みます。地図の移動・拡大縮小ではメッシュを自動切替しないため、大容量
  GML の意図しないパースを防ぎ、編集中の対象を安定して保てます。
- 編集は XML を再シリアライズせず、**原文バイト列の葉値だけを文字列置換**します
  （UTF-8 BOM・CRLF・字下げ・要素順を保持。W6 最小差分ゲートと整合）。
- `gml:id`・幾何・`uro:buildingID`・`core:creationDate` は常に読み取り専用です。
- PR は**一棟ごと**（複数棟の変更は CI が機械却下するため、UI で最初から作らせません）。
- 提出前チェックはローカルで完結し、ファイルを書き換えずに変更後の状態を検査します。
  送信時にも同じ検査を再実行し、詳細なXSD等は送信後のCIで確認します。
- コミットは `属性修正(<属性名>): <旧> → <新>` ＋ `Building: <uro:buildingID>` trailer
  （`scripts/suggest_commit.py` と同じ規約。`git log --grep "Building: <id>"` が効きます）。
