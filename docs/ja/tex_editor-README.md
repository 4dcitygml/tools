# CityGML LOD2 テクスチャエディタ

建物の**外観写真（LOD2 テクスチャ）の置き換え・新規付与**に特化したローカルツール。
[属性エディタ](attr_editor-README.md) の姉妹ツールで、
「2D地図で建物を選ぶ → 3D/面リストで面を選ぶ → 写真を切り抜いて貼る → PR」の1フローを提供します。
テクスチャ未収録の LOD2 データにも、同じ操作で写真を**新規付与**できます（#119）。

## 起動

```bash
python3 tools/tex_editor/app.py        # → http://localhost:8766 が開く
```

- 依存は Python 3.9+ のみ（共通機構は attr_editor/app.py を読み込んで再利用）。
- クローン内から起動すれば `--repo` は自動検出。属性エディタと同時起動できます（ポートが別）。
- 属性エディタと同じく、メッシュ選択は意図的に手動です。メッシュ枠をクリックした場合にだけ
  建物フットプリントを読み込み、地図の移動・拡大縮小だけでは自動切替しません。

## 使い方

1. 地図のメッシュ枠 → 建物をクリック（LOD2 を持つ建物が対象。テクスチャ未収録の建物は
   **新規付与モード**になり、無地のプレースホルダに対して同じ操作で貼れます）
2. 右ペインの**壁カード**（ファサードの合成サムネイル）または **3D ビューの面クリック**で壁を選択
   - LOD2 の壁は階帯ごとの細かいポリゴンに分割されているため、**法線方位でグルーピング
     した「壁」単位**で編集します（例: 40面の高層ビル → 壁4枚＋屋根等）。屋根などは単面編集
3. 写真をドラッグ＆ドロップ → **四隅を 左上→右上→右下→左下 の順にドラッグ**で壁全体に合わせる
   （あおり・台形は自動補正）→［適用］で、**壁を構成する全ポリゴンへ自動で焼き分け**て 3D にプレビュー
   - 焼き分けは textureCoordinates とポリゴン頂点の1対1対応から面ごとのアフィン変換を
     最小二乗で解いて行うため、向き・反転・細い帯も正確に処理されます
4. 適用すると、右ペインの平面画像比較より上に**変更前／変更後の3D建物を横並び**で表示します。
   どちらかを回転・拡大するともう一方も同じ視点へ同期するため、建物全体への馴染みを直接比較できます。
   その下には壁・面ごとの**変更前／変更後の平面画像**を表示します。左側の編集用3Dも
   ［編集用3Dを変更前に切替］で一時的に元テクスチャへ戻せます
5. 複数の壁・面をまとめて編集可（同一建物内のみ）→ 納得できたら［プルリクエスト作成］。
   生成される PR タイトル・本文は**リポの作業言語**（`4dcitygml.json` の `lang`、
   hub README の「言語ポリシー」参照）で書かれます — commit メッセージは英語のままです。

### カメラ整合モード（写真1枚から一括貼付）

街角からの1枚で、写真に写っている面（塔屋・セットバックの見える側を含む）をまとめて更新できます。

1. ［📷 写真1枚から一括貼付］→ 写真をドロップ
2. **3Dビューの黄色い頂点マーカー → 写真上の同じ場所**、の順にクリックして対応点を6組以上指定
   - **壁の下端の点を選ぶと、大きな指示文が出ます**: 写真では壁の根元ではなく
     **屋根の角の真下（地面との境目）**をクリックしてください。モデルの壁は屋根外周線
     （軒先線）から鉛直に降ろした面のため、軒の出がある建物では実物の壁の根元と一致しません
     （#109 の対応点ずれの汎用対策。屋根角＋その真下のペアで取ると高さ方向に分離した
     対応点が確保でき、位置合わせが安定します）
3. ［位置合わせ］→ カメラ姿勢を推定（正規化DLT）し、水色のワイヤーフレームが写真の建物に
   重なることを確認（再投影誤差を表示。ずれていれば対応点を追加）
4. ［貼付候補を作成］→ 面ごとに**可視判定つきパッチ**を生成し、チェックボックスで採否
   （見えている割合を表示。3Dでプレビュー確認）→［適用］

**見えない画素は元のテクスチャを維持します**（カメラの背面・自建物による遮蔽・フレーム外は
zバッファ判定で除外し、境界はフェザリング）。別の角度の写真で繰り返せば
建物全体が徐々に更新されていきます。注意: 隣の建物・街路樹など**自建物以外の遮蔽物**は
判定できないため、写り込んだ面はチェックを外してください。
   - 使用した写真は **CC0 1.0** での提供に同意して提出します（[データ貢献ポリシー](https://github.com/4dcitygml/city-template/blob/main/docs/data-contribution-policy.md)。顔・ナンバー等への配慮を含む）

## 編集方式 — アトラス焼き込み（設計の要点）

実データでは「1画像 = 1 ParameterizedTexture・建物間の画像共有なし・
同一建物内の複数面が1画像（アトラス）を共有」という構造のため、置き換えは:

1. ブラウザの canvas で写真を台形補正し、**元アトラス画像のコピーの UV 領域へ焼き込み**
2. 新画像を **content-addressed 名（`tex_<sha256先頭12>.jpg`）で新規追加**（既存画像は触らない = R1）
3. GML は該当 `app:imageURI` **葉値1つを一意一致検証つきで置換**（UV・XML構造は不変）

これにより差分は「GML 1行＋新画像1ファイル」の最小になり、既存 CI と整合します
（texture_check が appearance 変更建物 (a) として1棟に算入 → classification=single、
R3 dangling チェックも新画像の同時コミットで合格）。
万一アトラスが複数建物で共有されている場合、その面は編集不可と表示します（保険）。

## 色調（トーン）合わせ

- 提出写真は適用時に**「置き換える面の現在の色調」へ自動補正**されます（一括変換後の
  街は日なた/日陰の方向性が焼き込まれているため、全市共通の目標値ではなく面ごとの
  実測ターゲットに合わせる。北面は北面らしく、南面は南面らしく）。YCbCr で輝度は
  平均・分散、色差は平均のみ＝ホワイトバランス。彩度は保持するので塗り替え等の
  意図した色変化は消えません。「強さ」スライダーと明るさ・色温度の手動微調整つき。
  `tone_standard.json` は一括変換（初期整備）用の基準です
- 既存テクスチャ全体の一括変換（公開前の初期整備）は `scripts/retone_textures.py`
  （--stats / --write-standard 参照写真 / --preview / --apply。Pillow 使用）。
  一括側は**街全体で単一の変換**（建物間の明暗の個性を保存）、提出側は**写真ごと**に
  基準へマッチ（撮影条件の差を吸収）という役割分担です

### チームでトーンを見比べる（決勝戦スクリプト）

```bash
python3 tools/tex_editor/tone_battle.py                 # 原本 / lift=100 / 115 / 130 の4タブが開く
python3 tools/tex_editor/tone_battle.py --lifts 105,120       # 候補を変える
```

3D確認で「暗いのは露出不足ではなく**焼き込まれた日陰**（日なた面は適正）」と判明したため、
既定は**シャドウリフト方式**（暗部のみ持ち上げるトーンカーブ・日なたは不変）です。
1枚のアトラス内に日なた面と日陰面が混在していても正しく効きます。決まったら
`python3 scripts/retone_textures.py --set-lift <値>` で基準を確定してください。

候補トーンの変換済みテクスチャを自動生成（初回のみ数分・Pillow 必要）し、同じ建物を
開いたタブをトーンごとに並べます（ヘッダにトーン名表示・ヘッダ色も変わるので取り違え
なし）。3D パネルで LOD2 → テクスチャ を押して見比べ、上記の `--set-lift` コマンドで
選んだ値を基準へ記録してください。

### 撮影のコツ

- **できれば曇天か日陰の時間帯に**（晴天は太陽影が壁に焼き込まれ、補正で消せません）
- 壁面になるべく正対し、レンズ歪みの影響を避けるため被写体を写真の中央寄りに
- 顔・ナンバープレート等への配慮は[データ貢献ポリシー](https://github.com/4dcitygml/city-template/blob/main/docs/data-contribution-policy.md)参照

## 対応範囲

- 既存テクスチャがある面の**置き換え**（v1）
- テクスチャ未収録の建物への**新規付与**（#119）:
  - **1棟1アトラス・初回のみ新規経路**: 初回付与時に建物の全 LOD2 壁面の UV を一括定義した
    アトラスを生成（未撮影の壁は無地のプレースホルダ画素）。**2回目以降は置き換えモードに合流**
  - UV は壁クラスタ（法線方位）の壁座標 s×h から生成。**対象は壁のみ**（屋根面への新規貼付・削除は対象外）
  - GML への書き込みは appearance ブロック1個の挿入のみ（`xmlns:app` は要素ローカル宣言・
    既存要素と幾何は不変・BOM/CRLF 保持・R1/R3 と CI 検査に整合、XSD 検証済み）
  - 新規付与ではトーン自動補正を行いません（「置き換える面の現在の色調」が存在しないため。
    明るさ・色温度の手動調整は可能）
- 焼き込みでアトラス全体を JPEG 再エンコード（quality 0.92）するため、
  同一アトラスの他の面もわずかに再圧縮されます（見た目は実質不変）
